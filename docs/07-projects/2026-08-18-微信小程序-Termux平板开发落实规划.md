# 微信小程序开发落实规划（Termux · 安卓平板环境）

> **关联讨论**：个人盈利路径、垂直小工具（库存 / 巡检 / 报修）、网页 + APK 热更新与小程序并存策略。  
> **本文定位**：在**不依赖 Windows/Mac 常驻开发机**的前提下，把小程序从注册到 MVP 交付拆成可执行阶段；明确哪些步骤必须在平板/Termux 完成、哪些必须借助手机微信或偶发 PC。  
> **实现提示词**：[MyInventory Agent 实现提示词](2026-08-18-MyInventory-Agent实现提示词.md)（MyInventory 仓 Agent 一句话即可启动）。

## 0. 环境可行性结论（先读）

### 可以直接在安卓平板 + Termux 做的事

| 能力 | 说明 |
|------|------|
| **写代码** | 原生小程序（WXML/WXSS/JS/JSON）或 uni-app/Taro 源码；配合 Cursor Web 在 Git 仓库里迭代 |
| **版本管理** | `git` 克隆、提交、拉取 |
| **依赖与构建** | Termux 内 `node` / `npm`；Taro/uni-app 编译（资源占用较高，建议平板内存 ≥ 6GB） |
| **预览** | 官方 [`miniprogram-ci`](https://developers.weixin.qq.com/miniprogram/dev/devtools/ci.html) 的 `preview`：终端输出**预览二维码**，用手机微信扫码真机调试 |
| **上传体验版** | `miniprogram-ci upload` 上传到微信后台，在小程序助手或公众平台设为体验版 |
| **后端** | 微信**云开发**（免自建服务器备案）或轻量 VPS API（需备案域名） |
| **与现有栈复用** | 管理端继续用网页；现场录入用小程序；可选保留 Termux APK 壳作为备用交付形态 |

### 不能在平板 Termux 原生完成的事

| 限制 | 影响 | 替代方案 |
|------|------|----------|
| **微信开发者工具（GUI）无安卓版** | 无官方模拟器窗口 | 以**真机预览**为主；偶发借用 PC 打开 DevTools 查布局 |
| **微信公众平台网页操作** | 注册、类目、审核、发布须在浏览器完成 | 平板浏览器登录 [mp.weixin.qq.com](https://mp.weixin.qq.com) 即可，不必 PC |
| **微信支付、部分开放能力** | 个人主体不可用 | MVP 阶段不做支付；企业主体后续再加 |
| **request 合法域名** | 自建 API 须备案域名 | 首版优先**云开发**，或 MVP 仅云函数 |

### 总判断

**可以落实。** 你的环境适合采用 **「Cursor 写码 + Termux 构建/上传 + 手机微信真机测」** 流水线；不必等买电脑再开工。唯一要接受的是：**没有模拟器，调试节奏是「改代码 → CI 预览 → 扫码」**，比 PC 慢约 30%～50%，但一个人做 MVP 完全够用。

## 1. 问题与目标

### 1.1 要解决的问题

- 小微企业 / 小仓库 / 门店需要**轻量录入与查询**，不愿装复杂 ERP，但希望**微信里就能用、能分享**。
- 你个人开发者需要：**一套后端、多种前端**（网页管理 + 小程序现场 + 可选 APK），且开发环境以**平板 + Termux** 为主。

### 1.2 MVP 产品定义（第一版建议）

**名称（示例）**：轻量现场助手 MVP  
**首选垂直**：**小仓库存 + 扫码录入**（可替换为巡检 / 报修，架构相同）

| 角色 | 端 | 核心功能 |
|------|-----|----------|
| 老板 / 文员 | 网页管理端（已有 Cursor 网页经验） | 商品/物料列表、入库出库记录、简单库存、导出 CSV |
| 现场员工 | 微信小程序 | 微信登录、扫码或手输入库/出库、查看当前库存、拍照备注（可选） |

**MVP 不做**：多门店权限体系、微信支付、复杂报表、AI  Agent（留 v1.1 溢价）。

### 1.3 成功标准（可验收）

1. 平板 Termux 一条命令生成预览码，手机微信能完成**登录 → 录入 → 查询**。
2. 网页端与小程序**读写同一数据源**。
3. 体验版上传成功，可给 1 个试点客户扫码使用。
4. 文档 + 脚本齐全，换项目可复用仓库模板。

## 2. 技术方案

### 2.1 架构总览

```
┌─────────────────┐     ┌─────────────────┐
│  网页管理端      │     │  微信小程序      │
│  (GitHub Pages  │     │  (WXML/JS 或     │
│   或静态托管)    │     │   uni-app)       │
└────────┬────────┘     └────────┬────────┘
         │                       │
         └───────────┬───────────┘
                     ▼
         ┌───────────────────────┐
         │  微信云开发（推荐 MVP）  │
         │  · 云数据库            │
         │  · 云函数（鉴权/业务）   │
         │  · 云存储（照片，可选）   │
         └───────────────────────┘
```

**为何 MVP 选云开发**

- 免备案域名配置（小程序直连云开发）。
- 个人主体可开通，适合第一单试点。
- 后端逻辑集中在云函数，平板只需维护前端仓库。

**后续演进**：客户增多后可迁到自建 API（与网页共用 Node/Python 后端），小程序仅改 `wx.cloud` 为 `wx.request`。

### 2.2 仓库结构（单 monorepo 建议）

```
wechat-mvp/
├── miniprogram/          # 小程序前端（或 dist 输出目录）
│   ├── app.js
│   ├── app.json
│   ├── pages/
│   │   ├── index/        # 首页 / 库存概览
│   │   ├── scan-in/      # 入库
│   │   ├── scan-out/     # 出库
│   │   └── item-list/    # 物料列表
│   └── utils/
├── admin-web/            # 网页管理端（可与现有 site/ 模式一致）
├── cloudfunctions/       # 云函数（若用云开发）
│   ├── login/
│   └── stock/
├── scripts/
│   ├── preview.sh        # Termux 一键预览
│   └── upload.sh         # Termux 一键上传体验版
├── project.config.json
├── package.json
└── README.md
```

### 2.3 技术选型对比

| 方案 | 平板友好度 | 学习成本 | 建议 |
|------|------------|----------|------|
| **原生小程序** | 高（无构建或构建最轻） | 中 | **MVP 首选** |
| uni-app | 中（构建慢、占内存） | 中 | 以后要编译多端时再迁 |
| Taro | 中 | 中高 | 团队 React 栈时考虑 |

## 3. 微信侧前置条件（平板浏览器即可完成）

### 3.1 注册与开通

1. 打开 [微信公众平台](https://mp.weixin.qq.com) → 注册**小程序**（个人或企业）。
2. 记录 **AppID**（开发 → 开发管理 → 开发设置）。
3. 开发 → 开发管理 → 接口设置 → 开通**云开发**（创建环境，如 `mvp-xxx`）。
4. 设置 → 基本设置 → 服务类目（选与库存/工具类相近类目，影响审核）。

### 3.2 上传密钥（给 miniprogram-ci 用）

1. 开发 → 开发管理 → 开发设置 → **小程序代码上传密钥** → 生成。
2. 下载 `private.<appid>.key`，**切勿提交 Git**。
3. 平板路径建议：`~/.wechat-miniprogram/private.<appid>.key`（权限 `chmod 600`）。

### 3.3 人员与体验版

- 管理员微信号绑定后，用**小程序助手** App 管理体验版成员。
- 试点客户加入体验名单即可扫码，无需正式发布。

## 4. Termux 环境搭建（安卓平板）

### 4.1 基础包

在 Termux 中执行（与现有 APK 构建环境并存，注意 Node 版本别冲突时可使用 `nvm`）：

```bash
pkg update && pkg upgrade -y
pkg install -y git openssh curl
# 若尚未安装 Node（你已有构建环境可跳过）
pkg install -y nodejs-lts
node -v && npm -v
```

### 4.2 项目初始化

```bash
cd ~/projects   # 自定工作目录
git clone <你的仓库地址> wechat-mvp
cd wechat-mvp
npm install
npm install miniprogram-ci --save-dev
```

### 4.3 密钥与配置

```bash
mkdir -p ~/.wechat-miniprogram
# 将 private.<appid>.key 放到上述目录（通过平板文件管理器或 scp）
export WECHAT_APPID="wx********"
export WECHAT_PRIVATE_KEY_PATH="$HOME/.wechat-miniprogram/private.${WECHAT_APPID}.key"
```

`project.config.json` 中 `appid` 与 `miniprogramRoot` 指向正确目录。

### 4.4 一键预览脚本（`scripts/preview.sh`）

```bash
#!/data/data/com.termux/files/usr/bin/bash
set -euo pipefail
cd "$(dirname "$0")/.."
npx miniprogram-ci preview \
  --pp ./miniprogram \
  --pkp "$WECHAT_PRIVATE_KEY_PATH" \
  --appid "$WECHAT_APPID" \
  --project-path . \
  --qrcode-format terminal \
  --qrcode-output-dest "$HOME/wechat-preview.txt"
cat "$HOME/wechat-preview.txt"
echo "用微信扫描上方二维码进行真机预览"
```

### 4.5 一键上传体验版（`scripts/upload.sh`）

```bash
#!/data/data/com.termux/files/usr/bin/bash
set -euo pipefail
cd "$(dirname "$0")/.."
VERSION="${1:-0.1.0}"
DESC="${2:-mvp upload from termux}"
npx miniprogram-ci upload \
  --pp ./miniprogram \
  --pkp "$WECHAT_PRIVATE_KEY_PATH" \
  --appid "$WECHAT_APPID" \
  --project-path . \
  --version "$VERSION" \
  --desc "$DESC"
echo "上传完成：在公众平台/小程序助手设为体验版"
```

### 4.6 与 Cursor 的协作方式

| 步骤 | 在哪里做 |
|------|----------|
| 功能设计、大量写码 | Cursor Web Agent（推送到 Git） |
| 拉代码、预览、上传 | Termux `git pull` + `bash scripts/preview.sh` |
| 真机测试 | 手机微信扫预览码 |
| 给客户演示 | 体验版二维码（小程序助手） |

## 5. 开发阶段与里程碑

### 阶段 P0 — 账号与流水线（约 3～5 天，含审核等待）

| 任务 | 产出 | 完成标准 |
|------|------|----------|
| 注册小程序 + 云开发 | AppID、云环境 ID | 云控制台可建集合 |
| Termux 装 Node、拉仓库 | 可运行 `npm install` | 无报错 |
| 配置 miniprogram-ci | `preview.sh` 跑通 | 手机能打开空白首页 |
| `.gitignore` 排除密钥 | 安全 | 密钥不进仓库 |

### 阶段 P1 — 数据层与登录（约 1 周）

| 任务 | 产出 | 完成标准 |
|------|------|----------|
| 云数据库集合设计 | `items`、`stock_logs` | 字段文档写入 README |
| 云函数 `login` | 基于 openid 的用户记录 | 小程序可拿到 openid |
| 基础权限规则 | 数据库安全规则 | 仅登录用户可读写本租户数据 |

**集合字段（示例）**

- `items`：`{ _id, name, barcode, unit, quantity, updatedAt }`
- `stock_logs`：`{ itemId, type: 'in'|'out', qty, note, operatorId, createdAt }`

MVP 租户策略：单客户单环境；多客户以后用 `tenantId` 字段扩展。

### 阶段 P2 — 小程序核心页（约 1～2 周）

| 页面 | 功能 | 优先级 |
|------|------|--------|
| `index` | 今日出入库笔数、低库存提示 | P0 |
| `scan-in` / `scan-out` | `wx.scanCode` + 数量输入 + 提交 | P0 |
| `item-list` | 搜索、库存列表 | P0 |
| `item-detail` | 最近流水 | P1 |

交互原则：**主流程 ≤ 3 步**（扫码 → 数量 → 确认）。

### 阶段 P3 — 网页管理端（约 1 周，可与 P2 并行）

| 功能 | 说明 |
|------|------|
| 物料 CRUD | 表格增删改 |
| 流水查询 | 按日期筛选 |
| 导出 CSV | 给客户备份，降低信任成本 |

网页通过云开发 Web SDK 或云函数 HTTP 接口访问（按你熟悉程度二选一）。

### 阶段 P4 — 试点与体验版（约 1 周）

| 任务 | 说明 |
|------|------|
| 找 1 个试点 | 闲鱼 / 熟人小仓；明确免费试点或低价 |
| 录入真实数据 50～100 条 | 暴露性能与交互问题 |
| 上传体验版 + 加体验成员 | 客户日常可用 |
| 写操作说明（1 页图） | 降低支持成本 |

### 阶段 P5 — 产品化（试点成功后）

- 多租户字段 `tenantId`。
- 换 Logo / 名称的**部署清单**（重复卖多家）。
- 年费维护合同模板（小修小改、云资源费）。
- 可选：同步提供 Termux APK 壳（弱网备用）。

## 6. 与「网页 + APK 热更新」的并存策略

```
客户类型 A：只用微信          → 小程序 + 网页
客户类型 B：不想用微信        → 网页 + APK
客户类型 C：现场微信、办公室网页 → 全套（推荐主推）
```

**后端统一**后，三种壳只是前端渠道，避免三套业务逻辑。

## 7. 差异化与盈利挂钩

| 差异化 | 说明 |
|--------|------|
| 交付快 | Cursor + 模板化，1～2 周可演示 |
| 微信免安装 | 比 APK 更易在小客户群推广 |
| 可导出 / 不绑架 | 小企业核心顾虑 |
| 你本人可维护 | 深圳本地可上门或远程，嵌入式背景可加**扫码枪 / 蓝牙 / 简易物联网**溢价 |

**报价参考（仅供规划，按客户调整）**

- MVP 定制：¥3,000～8,000（含小程序 + 简单网页）
- 年费维护：¥600～2,000 / 年
- 硬件监控扩展（ESP32）：项目费另计

## 8. 风险与应对

| 风险 | 等级 | 应对 |
|------|------|------|
| 平板无模拟器，调试慢 | 中 | 固定「预览脚本」节奏；核心逻辑放云函数单元自测 |
| Termux 编译内存不足 | 中 | MVP 用原生小程序；避免大型框架 |
| 微信审核不通过 | 中 | 类目准确、无违规文案、无未开放能力；先体验版试点 |
| 个人主体能力受限 | 低 | MVP 不需要支付；企业主体后补 |
| 密钥泄露 | 高 | 密钥仅本地；CI 用环境变量；Git 钩子检查 |
| 单客户定制拖垮 | 高 | 合同写清范围；80% 模板 + 20% 定制 |

## 9. 测试策略（无模拟器环境）

1. **云函数**：在云开发控制台在线测试 + 本地 `node` 跑纯逻辑（与 wx 解耦部分）。
2. **小程序**：每次合并主分支前 Termux 执行 `preview.sh`，手机走一遍冒烟用例：
   - 登录 → 入库 → 出库 → 列表数量正确 → 网页端同步。
3. **弱网**：手机开飞行模式切换，确认提示友好（云开发断网表现）。
4. **回归清单**：写在 `docs/` 或 `README`，试点前后各跑一遍。
