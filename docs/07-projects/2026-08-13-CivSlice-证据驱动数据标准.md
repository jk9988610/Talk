# CivSlice 证据驱动数据标准（v3）

> **本文件自 2026-08-13 起为 CivSlice 数据的最高规范**，取代「固定十维填表」与「无来源占位数据」做法。  
> 实现仓库：[CivSlice](https://github.com/jk9988610/CivSlice)  
> 关联：[史料方法论与数据规范](2026-08-12-CivSlice-史料方法论与数据规范.md)（历史参考）· [时代维度模板](2026-08-12-CivSlice-时代维度模板.md)（比较束，非必填表）

## 为什么要改

| 旧做法的问题 | v3 原则 |
|--------------|---------|
| 固定十维 / 固定核心五维 + 模块，逼空填 | **有证据才建条目**；无证据标 `absent` 或根本不建 key |
| AI、通史、维基概括直接标 `documented` | **每条断言必须可追溯到 `sources[]`** |
| `speculative` 与正式快照混存 | **正式数据禁止推测**；假说进独立假说库，不得进入快照 |
| 各国快照数量、年份对齐追求「好看」 | **年份由史料锚定**，不为对比整齐而挪年 |
| 维度 `level` 普遍填写 | **`level` 可选**；无已发布 rubric 则不填 |

> CivSlice 不是「文明打分游戏」，而是**有证据约束的历史状态记录与同时代对照工具**。

---

## 一、必须固定（不可妥协）

以下结构对所有文明、所有时代统一适用。

### 1. 记录单元：快照（Snapshot）

一条快照 = **在可考证时间锚点上**，对**特定政治体/文化体**在**特定空间范围**内的一条结构化记录。

| 字段 | 必填 | 说明 |
|------|------|------|
| `year` | 是 | 整数年份（公元前为负） |
| `yearUncertainty` | 否 | 如 `±50`、`terminus ante quem` |
| `eraLabel` | 是 | 人类可读时段名；有争议用考古文化名 + 注释 |
| `spatialScope` | 是 | 本条证据实际覆盖的地理范围，不得默认「全国」 |
| `polityId` | 推荐 | 政体/文化体 id（可与文明 id 不同，如「西周」「洛邑」） |
| `evidenceTypes` | 是 | 见 §2 |
| `evidenceNote` | 是 | 一句话说明本条快照证据链如何成立 |
| `sources` | 是 | 至少 1 条，见 §3 |
| `aspects` | 是 | 见 §4；可为空对象 `{}`（仅当除元数据外无任何可断言内容时） |
| `comparisonBundle` | 否 | 参与同时代对比时使用的比较束 id，见 §5 |

### 2. 证据类型（固定枚举）

| 值 | 含义 | 可作 `documented` 的依据 |
|----|------|---------------------------|
| `archaeology` | 遗址、器物、地层、测年 | 是（须指明报告/藏品编号） |
| `literature` | 文献、铭文、档案、书信 | 是（须区分 contemporaneous / 后世） |
| `epigraphy` | 铭文、碑刻、出土简牍 | 是 |
| `numismatics` | 钱币、度量衡实物 | 是 |
| `iconography` | 图像、艺术考古 | 视情况，常 `inferred` |
| `oral_tradition` | 口传、民族志采集 | 原则上仅 `inferred`，不当 `documented` |

**禁止**将以下当作 `sources`：

- AI 训练记忆、模型「常识」
- 无具体条目的「通史」「学术共识」
- 维基百科条目本身（可作线索，须追到原始文献或考古报告）
- 未标注出处的二手科普

### 3. 来源（Source）— 每条快照的核心

```json
{
  "id": "src-zuozhuan-xi-28",
  "type": "literature",
  "ref": "《左传·僖公二十八年》",
  "relation": "contemporaneous",
  "locator": "中华书局点校本",
  "note": "可选：与本条断言的具体对应"
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | 是 | 快照内唯一，供 `sourceRefs` 引用 |
| `type` | 是 | 上表枚举或 `archaeology` / `literature` 等 |
| `ref` | 是 | **可核查**的具体出处（书名+卷次、报告名+页码、遗址编号） |
| `relation` | 推荐 | `contemporaneous` / `near_contemporaneous` / `later_retrospect` |
| `locator` | 推荐 | 版本、页码、图录号、发掘简报链接 |
| `note` | 否 | 局限性、立场、保存状况 |

**硬规则**：`aspects` 中任何 `confidence: documented` 的条目，`sourceRefs` 不得为空。

### 4. 断言（Aspect）— 取代「固定维度表」

不再维护「每条快照必须填满 N 个维度」。改为 **按证据出现的主题（aspect）** 记录断言。

```json
"aspects": {
  "irrigation_agriculture": {
    "confidence": "documented",
    "summary": "关中郑国渠等灌溉工程见于文献与水利遗迹",
    "sourceRefs": ["src-shiji-hequ", "src-excav-report"],
    "level": null
  },
  "coinage": {
    "confidence": "absent",
    "note": "检索范围：该时段中原出土货币报告与文献；未发现统一铸币证据"
  }
}
```

#### 4.1 可信度（固定四级，快照内只用三级）

| `confidence` | 含义 | 允许写入正式快照 |
|--------------|------|------------------|
| `documented` | 有直接证据支撑 | 是 |
| `inferred` | 由相邻证据合理推论，逻辑链在 `note` 写明 | 是 |
| `absent` | 已检索，证据不足 | 是 |
| `speculative` | 假说 | **否** — 见 §6 假说库 |

#### 4.2 `absent` 的写法（强制显式）

无数据时**二选一**，推荐 a：

a. **显式 absent**（推荐 — 表示「已检索」）：

```json
"aspect_id": {
  "confidence": "absent",
  "note": "检索范围：…；未发现…"
}
```

b. **省略 key** — 仅用于「未检索、不在本条快照研究范围内」；不得用于偷懒掩盖应检索的主题。

**禁止**：用 `level: 0`、空 `summary` 或随便填 `inferred` 代替 `absent`。

#### 4.3 `level`（1–5，可选）

- 仅当该 `aspect` + 该时代 **已有书面 rubric**（评分说明）时才可填
- 无 rubric → `level: null` 或省略
- `level` 表示**该政治体内部**相对程度，**禁止**跨文明排名
- `absent` 条目不得有 `level`

#### 4.4 Aspect 从哪来（不固定清单）

| 层级 | 说明 |
|------|------|
| **开放目录** | `meta/aspectCatalog.json` 收录已用 aspect id 与定义，可扩展 |
| **比较束建议** | 同时代对比时，从比较束（原时代模板）**选取**可能相关的 aspect，有则填、无则 `absent` |
| **禁止** | 为凑满雷达轴而新建 aspect 或硬填 |

初始 catalog 可从 [时代维度模板](2026-08-12-CivSlice-时代维度模板.md) 的 core + modules **迁移为标签**，但**不再是必填字段集**。

### 5. 比较束（Comparison Bundle）— 非固定维度，仅对齐同时代对比

同时代横向对比时，参与国应声明同一 `comparisonBundle`（如 `axial_age_eurasia`），UI 只对比该束内 **各方已有数据或显式 absent 的 aspect**。

- 比较束 = **建议关注的主题集合**，不是每张快照的必填表
- 某国某 aspect 为 `absent` → 雷达上显示缺口，**不计为 0 分**
- 跨束、跨时代纵向对比：UI 须提示「维度集不可直接叠图」

原 `eraTemplate` 可保留为比较束别名，逐步迁移为 `comparisonBundle`。

### 6. 假说库（与快照严格分离）

推测、争议假说、待检验观点 **不得** 写入 `aspects`。

```json
{
  "id": "hyp-001",
  "claim": "二里头遗址等于整个夏王朝都城",
  "status": "rejected",
  "refutedBy": "遗址年代范围与文献夏代纪年不完全吻合",
  "sourceRefs": ["src-erlitou-report-2020"],
  "relatedSnapshots": ["china:-2000"]
}
```

`status`: `pending` | `supported` | `rejected` | `withdrawn`

## 二、刻意不固定（灵活）

| 项目 | 说明 |
|------|------|
| Aspect 数量与种类 | 完全由证据驱动 |
| 每国快照数量 | 由已考证时间点决定，不凑数 |
| 快照年份 | 不强制各国对齐；`worldContext` 可写同期他国作背景，不作本国证据 |
| `level` | 有 rubric 才填 |
| 区域导航、时段 Tab | UI 层，见 [区域导航](2026-08-13-CivSlice-区域导航与比较选择.md) |
| 派生对比指标 | 运行时从**已有 aspect** 计算，禁止写入 JSON |
| 比较束列表 | 可增删，须文档化每个束的 aspect 建议与适用年份 |

## 三、工作流程（AI 与人类均须遵守）

### 3.1 新建或修订一条快照

```
1. 定锚 — 年份、政体、spatialScope 能否由来源支撑？
2. 列来源 — 先写 sources[]，再写 aspects（禁止反过来）
3. 拆断言 — 每条 aspect 只陈述来源能支撑的一句话
4. 定可信度 — documented / inferred / absent
5. 标 absent — 比较束内已检索却无材料的主题，显式 absent + 检索范围
6. 禁推测 — 想写但无链 → 进假说库或放弃
7. 复核 — documented 是否均有 sourceRefs；ref 是否可核查
```

### 3.2 AI 助手专用约束

| 允许 | 禁止 |
|------|------|
| 从用户提供的文献列表结构化 | 用训练记忆生成「各国通史快照」 |
| 标 `inferred` 并写清推理链 | 把通史常识标 `documented` |
| 大量标 `absent` | 为美观填满 aspect |
| 起草后交人工审核 | 未经审核直接标 `documented` |
| 建议比较束与待检索清单 | 伪造 `sources.ref` |

### 3.3 审核清单（PR 合并前）

- [ ] 每条 `documented` 有 `sourceRefs` 且 ref 可核查
- [ ] 无 `speculative` 出现在 `aspects`
- [ ] 比较束内已声明检索的 aspect，无证据的已标 `absent`
- [ ] `eraLabel` 与 `year` 匹配，争议时段已注释
- [ ] 无「以今证古」表述
- [ ] 现代政体与古代政体未混为连续 `polityId`（须注断裂）

## 四、JSON Schema 概要

### 4.1 文明文件

```json
{
  "meta": {
    "countryId": "china",
    "country": "中国",
    "color": "#b22222",
    "methodology": { "version": "3.0" },
    "rejectedHypotheses": [],
    "aspectCatalogVersion": "2026-08-13"
  },
  "snapshots": []
}
```

### 4.2 快照（完整示例）

```json
{
  "year": -500,
  "yearUncertainty": "±20",
  "eraLabel": "春秋末期",
  "spatialScope": "中原华夏诸侯国（非全体「中国」）",
  "polityId": "eastern_zhou_states",
  "comparisonBundle": "iron_imperial_axial",
  "evidenceTypes": ["literature", "archaeology"],
  "evidenceNote": "《左传》编年 + 诸侯墓葬考古；不含未证实的具体战役细节",
  "sources": [
    {
      "id": "src-zuozhuan",
      "type": "literature",
      "ref": "《左传》",
      "relation": "contemporaneous",
      "locator": "相关卷次随 aspect 注明"
    },
    {
      "id": "src-houma",
      "type": "epigraphy",
      "ref": "侯马盟书",
      "relation": "contemporaneous"
    }
  ],
  "aspects": {
    "geography": {
      "confidence": "documented",
      "summary": "华夏核心在黄河中下游，向江淮扩展",
      "sourceRefs": ["src-zuozhuan"]
    },
    "iron_metallurgy_spread": {
      "confidence": "documented",
      "summary": "铁器开始在中原部分区域出现",
      "sourceRefs": ["src-houma"]
    },
    "unified_coinage": {
      "confidence": "absent",
      "note": "春秋诸侯货币形态多样，未见统一国家铸币证据"
    }
  },
  "controversies": [
    "战国时代起点有前475年、前403年等不同划分"
  ]
}
```

### 4.3 与旧十维 / 时代模板的兼容

CivSlice 实现层可保留 `dimensions` → `aspects` 映射器，服务旧 `china.json`。**新数据只写 `aspects`**。迁移时：

- 旧字段无来源 → 降级 `absent` 或删除
- 旧 `speculative` → 移入假说库或删除
- 旧泛化 `sources` → 必须替换为可核查 ref

## 五、UI 与派生指标

| 组件 | v3 行为 |
|------|---------|
| 剖面雷达 | 只绘制当前快照 **非 absent** 的 aspect；轴数动态，不固定 10 |
| 对比雷达 | 只比较选定比较束内、各方有数据的 aspect；`absent` 不参与、不当 0 |
| 维度卡片 | 显示 `summary` + 来源链接 + 可信度 |
| 空状态 | 「未检索」与「已检索无证据」分开展示 |

派生指标规则不变：[对比雷达与派生指标](2026-08-12-CivSlice-对比雷达与派生指标.md)，但输入改为**当前可见的 aspect 子集**。

## 六、对现有数据的处理原则

| 数据类型 | 处理 |
|----------|------|
| `china.json` 有具体来源者 | 迁移为 `aspects` + `sourceRefs` |
| 各国通史占位数据（无具体 ref） | **下架或全部标 absent**，不得保留假 `documented` |
| AI 批量生成的国家 JSON | 停用，按本标准从零考证或删除 |
| 旧十维字段 | 只读兼容，不新增 |
